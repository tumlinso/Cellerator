# FP64 prepared relation support

The prepared sparse relation provider supports these relation-value and
feature-storage pairs:

| Relation values | Features | Multiply, accumulation, output |
| --- | --- | --- |
| FP32 | FP32 | FP32 |
| FP32 | FP64 | FP64 |
| FP64 | FP32 | FP64 |
| FP64 | FP64 | FP64 |

The two mixed pairs retain the stored operand precisions and promote each
operand before multiplication. FP64 is useful when cancellation or numerical
requirements exceed FP32's range and precision. It should not be selected as a
default promotion: FP64 relation values and feature/output buffers each use
twice the storage of FP32, and FP64 arithmetic may reduce throughput on some
devices. Measure the workload on its target device before choosing it.

FP16 retains its existing explicit low-precision route. Typed relation values
use `device_numeric_values_binding<T>`, aliased as
`device_f32_values_binding` and `device_f64_values_binding`, with
`publish_f32_values` and `publish_f64_values`. State and result views add a
trailing dtype field defaulted to FP32 for existing callers. FP64 does not add
gradient or derived-FP16 execution.

Prepared topology and transpose projections remain reusable across value
generations. The typed value plane follows the relation-value dtype; state and
result views declare their element dtype, and capacity is measured in elements
before conversion to bytes. Byte-range overflow, alignment, dtype and overlap
checks happen before output submission. Unsupported tuples fail explicitly.
The native elementwise multiply, square, and affine operations accept
homogeneous FP32 or FP64 buffers and use caller-owned storage.

The prepared masked-topology representation rejects duplicate source endpoints
within one row because it cannot retain their distinct edge slots. The shared
CSR traversal accepts duplicates and is qualified separately. Prepared
duplicate-edge execution is not supported.

Relation affine coefficients are represented as double. FP64 execution keeps
their double precision; FP32 execution rounds each coefficient to float at the
arithmetic boundary. This does not make cancellation-prone variance
universally stable. For variance, compare the second-moment identity with a
centered reference and choose precision based on the actual error requirement.

Qualification commands and the NumPy/SciPy input-storage-aware comparison are
in [tests/fp64](../../tests/fp64/README.md). Device timings, byte counts,
toolchain/device identity, and any observed FP32 regression belong in the
[FP64 qualification result](../results/fp64-qualification.md); do not infer
them from dtype size or this correctness harness.

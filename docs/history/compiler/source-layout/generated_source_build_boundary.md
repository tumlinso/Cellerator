# Generated source and build-tree boundary

Status: frozen for the Part One source-layout interface candidate.

Task: `CE-CCP1-A04-008`

## Generated output root

All Part One compiler-generated C/C++ sources, headers, manifests, tables, and
embedded resource arrays are written below the active binary directory:

```text
build/generated/Cellerator/compiler/
    frontend/parser/
    ir/dialects/
    backend/
    resources/
    build/
```

The literal `build/` denotes the configured binary directory, not a required
directory name. Out-of-source builds therefore use
`${CMAKE_CURRENT_BINARY_DIR}/generated/Cellerator/compiler/`. No generator writes
into `include/`, `src/`, `stdlib/`, `profiles/`, or another checked-in source
directory.

Generated parser tables live in `frontend/parser/`; CEIR dialect and operation
manifests live in `ir/dialects/`; backend registries live in `backend/`;
embedded standard-library/profile data lives in `resources/`; and public
version/feature headers live in `build/`.

## Checked-in generator inputs

Stable source schemas, templates, and generators are ordinary reviewed source:

| Output family | Checked-in inputs |
| --- | --- |
| parser tables | `src/compiler/frontend/parser/grammar/` and `src/compiler/frontend/parser/schemas/` |
| CEIR manifests | `src/compiler/ir/<level>/fragments/` and `src/compiler/ir/common/schemas/` |
| backend manifest | `src/compiler/backend/<provider>/fragments/` and `src/compiler/backend/schemas/` |
| embedded resources | `stdlib/manifest.json`, `.cell` sources, `profiles/reference/`, and resource schemas |
| version/features | `cmake/compiler/templates/`, project version, and configured feature inputs |

Generated output is not reviewed as authoritative source and is not committed.
Only selected public generated headers may be installed, and then only through
an explicit build/package rule under the `Cellerator/compiler/build/` include
prefix.

## Deterministic generation

Every generator:

1. consumes an explicit, sorted input list;
2. validates schema versions, stable identifiers, dependencies, and hashes;
3. rejects duplicate identifiers and undeclared inputs;
4. avoids timestamps, absolute paths, locale-dependent ordering, random values,
   and host-specific addresses in output;
5. emits the generator version plus source identities and content hashes; and
6. writes atomically only when generated bytes differ.

The reproducibility gate generates twice into separate empty binary roots with
the same declared inputs and compares the relative file list plus SHA-256 of
every output. A mismatch fails closed with the differing source/output identity.

## Clean-source-tree gate

The clean-tree gate starts from a clean checkout, configures and builds all
generated compiler targets out of source, runs their focused tests, and then
requires `git status --porcelain=v1 --untracked-files=all` to be empty. It also
requires `git ls-files 'build/generated/**'` to return no tracked output. The
repository's existing `build/` ignore rule is retained as defense in depth, not
as permission for a generator to write arbitrary source artifacts.

Generated headers are consumed through build-interface include paths. Installed
consumers see only the copied public subset; no installed header contains a
binary-directory absolute path.

## Current compatibility

The current build already uses `${CMAKE_CURRENT_BINARY_DIR}/generated` for
configured headers and provider manifests. The compiler subtree extends that
boundary without moving or reinterpreting existing runtime generation. This
task changes no current runtime or JBC behavior and introduces no Part Two JIT
or deep CellShard runtime work.

# Retained CellShard concrete application boundary

Todo `CE-CCP1-A03-010` preserves ten concrete responsibilities in CellShard:
atom-store containers, materialized instances, encoded replicas, file/object
storage, staging, placement, residency, transport, leases, and delivery. This
matches the JBC persistence/runtime plan reviewed with compiler source at
CellShard `b9749ad3e5146a04f847533d8c6f1a54146aed20`.

Each retained record consumes immutable Cellerator semantic identities,
compiled rulesets, exact coverage and realization requirements. None may
discover biological structure, define atom species or membership, certify
coverage, select a basis/superatom, define grammar, choose a portable ruleset,
or change domain/order identity. Concrete paths, object keys, addresses,
placement epochs, leases and device ordinals identify application instances
only and never enter compiler identity.

CellShard remains free to optimize storage formats, caching, I/O coalescing,
routes, replication, recovery and delivery under the compiled requirements.
That operational freedom is not semantic authority. Gate
`CE-CCP1-A03-010-GATE` checks the exact ten-row inventory is unique and every
row is marked application-only.

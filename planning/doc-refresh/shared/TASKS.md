# Four coarse outcomes per authority

## 10 — Reconcile the current tree and apply the written documentation

Inspect the then-current source/claims and upstream package completion; classify tracked/untracked documents with the supplied inventory tool; read unavailable QMD/JSONL locally. Start from the prepared README, design, developer, status and agent templates. Preserve managed workflow blocks. Consolidate conflicting introductions and label historical plans. Do not spend the task rederiving the scientific brief. Update bindings/current status when newer code justifies it. Stage and review the public documents; this package's draft prose should need editing, not reinvention.

**Accept:** one coherent public/agent/developer/status hierarchy, explicit source basis, no fabricated current capability, classification decisions and bounded remaining move set. A proposed source rename is not yet permission to erase evidence.

## 20 — Make only useful small moves, then bind final paths

Keep existing useful component separation. One mechanical cluster per repository by default, or no move. Resolve actual source/build/import/export/caller references, active scopes and evidence paths before moving. Repair sibling consumers within their own authorities if affected; no hidden cross-repository write. Preserve generated ledgers and immutable evidence; update live documentation validators that encoded obsolete page headings. Bind final paths after source work, run affected builds/tests, and record the map.

**Accept:** clearer navigation with unchanged numerical/scientific semantics, current build/use commands and clean internal links. No model/compiler completion, full reformat or forced external ABI preservation.

## 30 — Qualify and curate a small results section

Use the prepared shortlist, result JSON, tables, captions and chart renderer. Authenticate existing records and export small portable raw evidence where needed. Rerun only bounded selected cases when necessary, using scheduled resources. Keep all relevant density/reuse/control cases and unfavorable outcomes. At most two highlighted studies per repo; one optional GH synthetic capability wrapper total. Never use the oracle as product output. If data cannot be authenticated, publish a capability description with a limitation or omit it with a reason rather than inventing evidence.

**Accept:** selected result pages with checked metadata/raw links/reproduction, honest scope and disposition; selection rationale includes omitted candidates; no new broad benchmark campaign.

## 90 — Read the repositories as a visitor and finish the handoff

After final paths/data are bound, regenerate public files/figures, inspect normal and narrow rendered pages, follow a README→design→result→source path, and inspect figures in grayscale. Verify managed guidance, source-move record, links, source/benchmark claims and affected build/tests. Fill review flags only for completed actions. Emit one local receipt with actual qualified source and commands. The coordinator compares three receipts/shared terminology, not three duplicated status ledgers.

**Accept:** a reader can understand scientific intent, current code and evidence without reading internal plans; an agent finds operational authority quickly; no sibling boundary contradiction; transparent remaining limits. No push or external publication action is implied.

# Governing brief

## Purpose

A scientifically literate visitor should understand **why each repository exists, what is unusual about its approach, where to enter the code, and what evidence exists** without navigating thousands of files or task records. The public narrative is question → intuition → mechanism → demonstrated capability → limitations → entry points. The goal is not to impress by listing technologies.

Cellerator, Baseplane and GlassHelix are distinct components of one program. CellShard is an acknowledged sibling for persistence/distribution, but it is not a fourth cleanup target. CelleraTorch is part of Cellerator's adapter scope, not a separate authority to invent.

## Intent to preserve

**Cellerator:** a compiler/execution substrate that exploits structure in biological systems and the accelerator together. Discover reusable supports, modules or relations; compile them into executable representations, geometry, kernel generation/assembly and scheduling. The intended runtime is not static: cell state can gate/reorganize execution within prediscovered conditional structure. Existing mutable-value or bounded gate APIs are not proof that the full adaptive system is complete. The public wording must reflect the actual supported envelopes.

**Baseplane:** an attempt at online, hierarchical, learned floating-point representation of genome-wide information, grounded in exact sequence and accelerator execution. It cannot outsource the useful biological hierarchy to a genome-wide prediscovery oracle and then call that hierarchy discovered by the encoder. Representation may be built progressively or in more than one pass; “online” does not demand a one-pass irreversible stream. Pretrained operators, exact packing and ordinary data preparation are not prohibited. What cannot be assumed is the biological organization the model is meant to infer. Locality provides a cheap opportunity, not a cis/trans ontology or an explicit compulsory distance weight. Collective/predicated dataflow should make conditional computation practical at several scales. Exact-source retention/provenance does not make a finite embedding lossless or an attention explanation causal. CUDA is the near-term platform; FPGA/dataflow remains a longer-term possibility, not a new deliverable.

**GlassHelix:** investigate which biological states, dynamics and mechanisms the observations and interventions distinguish, and what useful partial information survives ambiguity. Predictive latent structure is not automatically molecular mechanism. Whole alternatives, shared responses, local sensitivities, evidence domains and non-identifiability are positive scientific objects. Eventually, supported mechanisms may become explicit state variables, dependencies or gates for Cellerator to specialize. A variable becoming explicit does not make its current value known: measurement, state estimation or an update law may still be necessary. Promotion is scoped, evidence-linked and reversible, not an eternal truth switch. No claim of automatic discovery/compilation unless the live code and tests show it.

**Shared hypothesis:** biological organization can shape computational organization; scientific learning may eventually change not only parameter values but also what is represented and which program runs. This is a hypothesis, not a proven asymptotic scaling law. Lower uncertainty need not reduce runtime in every case.

## Documentation roles

`README.md`: public explanation and a compact verified snapshot; no task archaeology.
`docs/design/`: durable concepts, mechanism, boundaries, rationale and deliberately open questions.
`docs/development/`: build/use/source map, contribution instructions and technical entry points.
`AGENTS.md`: concise operational contract, authority, preservation, edit/validation boundaries; preserve managed tool blocks.
`docs/status/current.md`: dated human synopsis, linked to current source and planned work; not another authoritative task ledger.
`docs/results/`: readable evidence, figures, metadata and portable links to raw records.
`planning/`, `todos*`, `.todo-orchestrator/`: plans and generated operational views; do not hand-edit or move generated state.
`docs/archive/`: historical narrative and retired design proposals, explicitly labeled and indexed. Immutable evidence is linked, not rewritten to match new prose.

## Limits

Documentation first; minor source reorganization only. No new universal API, general trainer, migration of every legacy kernel, central docs website or compulsory versioning bureaucracy. External compatibility may be broken when worthwhile, but real sibling consumers and scientific semantics must remain correct. Handle one small cluster at a time and record a mapping. A no-move decision is valid.

No mandatory benchmark victory. Prefer existing representative evidence; at most two highlighted results per repo. At most one new tiny capability fixture is provisioned in this package (GlassHelix). GPU execution is local/scheduled, never launched merely by rendering docs. Timing and quality/correctness conclusions remain distinct.

Final path references, build target names and post-package status are bound last. Prewritten prose should survive those changes. The implementing agent may improve a sentence but must not re-interview the user, revive superseded ideas, or use old AGENTS prohibitions to erase the now-authorized scientific intent. Resolve conflicting registered policy through its owner, never by falsifying ledger state.

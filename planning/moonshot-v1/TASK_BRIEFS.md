# Outcome briefs

These supplement, rather than duplicate, the native Todo completion contracts. Cellerator has seven implementation outcomes plus closure; GlassHelix has four plus closure. The task graph is intentionally coarse. Broad source integration happens late, after local prototypes can be exercised.

## CE-MOON-ADOPT

Bind current source/authority receipts and resolve overlap with CE-ML2-BIO. Stage the supplied code into a new experimental directory. Check the manifest and existing toolchain. Write a short decision stating additive integration versus an owner-approved selective supersession. Do not reset the active ML2 lane. Read only the source needed to adapt the first kernels; the review already identifies entry points.

## CE-MOON-MMA

Implement cards M01, M04 and the small M06 seed. Start from the provided CUDA source rather than rewriting templates. Add bounded admission: extents, alignment, dtype, aliasing, sentinel index rules and stream/device. Compile for70, execute the quad-MMA mapping smoke, and add one patch same-stored-half oracle plus a two-input JVP zero-case. Forward-only native status is acceptable here; DIFF owns the remaining derivatives.

Publish raw operator functions usable by a small native consumer. Inspect generated code enough to catch spills or accidental absence of MMA; no tuning sweep or speed claim is required. Preserve the old WMMA candidate.

## CE-MOON-STATE

Give the experimental state a practical nonowning representation: actor-local slot identity/incarnation, current value generation, physical order, structural support, trainable capacity, optional activity and residual mapping. A fixed dense tile is one view, not the entire ontology. Reuse CE stable IDs, placement and ownership at the adapter boundary.

Implement M05's port transport and M07's footprint placement. Keep private actor bases distinct. Show that two identical footprints are colocated but not merged. If model-specific encoders vary, do not silently share coefficients to get a bigger GEMM. Cost scoring may be a labeled heuristic until measurements exist.

## CE-MOON-DIFF

Implement requested patch and port input/parameter VJPs, plus a selected JVP. Use saved operands from the actual forward precision and generation. Reuse the current native owner/tape/CT registration patterns, including the completed nonmutating gradient path. Do not reintroduce hidden updates during backward.

Support FP32 reference and one explicit mixed policy. State whether derivatives treat stored values or use a quantization surrogate. A small adjoint identity and finite-difference witness suffice for each new mathematical expression. Ordinary Torch is an adapter/consumer, not a second numerical authority. Publish the first capability receipt for GH.

## CE-MOON-REWRITE

Implement supplied refactoring maps with model epochs. Begin with the exact invertible linear witness and the exact invariant-subspace quotient; introduce an actor with a hidden row and update the readout. Rebuild only affected projections, but use a full cold rebuild first if incremental repair would delay the prototype.

Keep physical replicas coherent and reduce their adjoints. Wait for or retain old tapes. Reset unsupported optimizer-coordinate migrations explicitly. Implement reusable capacity with a nondead initial gradient. Preserve trainable zero branches in derivative support. No support/Jaccard-driven scientific identity inference is required.

## CE-MOON-TRAJECTORY

Implement M03's linear-flow block with parameter-generation/dt keyed preparation and M10's delta ledger keyed to last transmission. Keep the zero-threshold/reference modes. Do not claim a whole-trajectory bound from the instantaneous linear discrepancy bound.

Choose one additional distinct experiment from M02, M11, M12 or M13. The implementation can be deliberately small: a quadratic matrix field, one low-rank feedback solve, one rate-law texture, or a two-component precision expansion. Keep the operator contract and derivative convention visible. No broad solver/runtime replacement.

## CE-MOON-INTEGRATE

Move selected reusable definitions into actual CE homes under reconciled scopes. Replace demo types with established identities/views and bind prepared_program_v2 stages. Keep experimental selectors explicit; preserve existing measured defaults. Repair real CT/GH consumer builds and affected checks.

Leave source and runnable examples even for hypotheses that are not yet faster. Record exact native capability and unsupported routes. Do not claim old CE-ML2-BIO complete-cost requirements are satisfied without either performing them or formally retaining them as separate work.

## GH-MOON-ADOPT

Reconcile DESIGN/LEARN scope and preserve REPAIR, DATA/PILOT/ACCEPT. Stage references. Mark initial model families as engineering hypotheses. Maintain joint scientific candidates and evidence boundaries.

## GH-MOON-MODELS

Train tiny examples using (1) a plain scalar-coordinate matrix patch or exact-flow predictor, and (2) an actor-local port model. Keep model assumptions distinct from physical layout. Use an externally supplied edge pattern first. A synthesized trajectory fixture establishes engineering capability only.

Substitute the actual native/CT operation when its capability receipt arrives. The independent Torch reference remains useful. Avoid introducing biological dataset constants into core GH.

## GH-MOON-REFACTOR

Demonstrate extraction/reassignment using a supplied map, then continue learning with live residual capacity. New actor names may be anonymous. Record before/after model definitions, state/readout correspondence and any approximation. Whole-model behavior and selected responses matter; coordinate resemblance alone is not scientific evidence.

A successful prototype can use the exact linear witness plus a learned residual branch. General nonlinear discovery, global identifiability and biological validation are not prerequisites.

## GH-MOON-CONSUMER

Expose a small model-level interface using current GH scientific roles and CE-backed computation. Provide usage for plain inference and supplied refactoring. Report which routes are native, reference-only or unimplemented. Keep later CellTag data/pilot/science work separate rather than blocking the exploratory program on it.

# NF1A execution charter

NF1A completes the accepted NF1 execution toolbox from preserved work. It replaces the unfinished procedural plan, not the program's scientific ambition or its successful history. Both local Todo UUIDs remain unchanged. Importing these packages starts no workers; a separate controller launch authorizes execution.

## What success means

A usable C++20 GlassHelix library and thin Python binding can describe supplied nonlinear systems, execute real Cellerator CPU/CUDA programs, evolve independent instances under supplied forcing, observe partial outputs, update a separate finite-candidate inferential state, interrogate directional response and local ambiguity, check supplied reductions, and replay a source-identified calculation. General-width FP32, an independent FP64 oracle, exact masked/compact alternatives, lifetime correctness and honest capability/error reporting remain required. The default demonstration requires real CUDA.

This is not a biological experiment, a final learner, universal mechanism discovery or a new compiler/runtime project. It does not settle GH-SCIENCE-FOUNDATIONS. The later scientific review's distinctions govern interpretation: answer sufficiency, dynamical closure, inferential sufficiency and molecular grounding are different. Natural excitation is not categorically excluded as identification evidence; NF1 nevertheless makes no new biological identification claim.

## Who decides what

The Astra root owns synthesis, consequential design decisions, integration and final acceptance. It should understand the mechanism and reason of intentional architecture, not follow an itinerary. Use ARCHITECTURAL_INTENT.md when those boundaries matter; use the source ledger to locate evidence, not as a compulsory reading list. Routine APIs, file layout, algorithms, test order, local retries and internal decomposition belong to the implementation owner.

Most substantial bounded work should go to appropriately capable cheaper children. A trivial direct fix may stay with Astra when dispatch and explanation would cost more. Terra/Luna are preferred where sufficient; Sol is available for demonstrably difficult work. Verify actual child model and effort once, then on material routing changes; never silently inherit an expensive root. No default parallel heads, recursive research hierarchy, fixed fan-out or mandatory independent review of every small patch. Existing role names are reusable, not a requirement to rebuild agent infrastructure.

Instructions are complete when the owner understands the outcome, rationale, relevant state, constraints, evidence and delegated choices. They need not enumerate every step. Preserve expensive discoveries as short, source-anchored findings; do not publish a diary. Re-fetch decisive or disputed evidence rather than repeating a child's full exploration. Local investigations are scouts: two independent questions with compute_profile=narrow when useful, direct reads when locations are known.

## Authority and autonomy

After the controller launch, there is explicit permission to create, edit, move, reorganize and selectively prune or replace bad, obsolete, duplicated or obstructive code in BOTH GlassHelix and Cellerator. Preserve useful behavior or replace it with qualified coverage. Do not mass-delete working code, destroy unknown/uncommitted/unmerged work, reset/clean source, force-push, remove unrelated worktrees or activate unrelated historical tasks.

The root may revise ordinary designs, split or combine local execution, change provisional API spelling, transfer scopes and correct regressions within NF1 without repeatedly asking the user. Record consequential commitments through the native authority, update affected consumers and check ownership conflicts. A scope is coordination, not a reason to build a duplicate engine. Defer to the user only for genuinely destructive or unapproved expansion, unavailable authority/resources, or a real contradiction.

## Completion and economy

Each outcome owns its relevant tests and local correction loop. Integrators stage source early; a final acceptance gate is not a claim-time prerequisite for integration. Preserve all substantive requirements in machine/requirements.json and the legacy mapping. Optimization evaluation is required; building every speculative optimization is not. Exact compaction, real GPU response, scientific distinctions and Python parity are not optional optimizations.

Use real device leases only when executing device work, and one host-shared lock for the paired evidence campaign. Never hold GPU resources throughout ordinary coding. Budget builds, memory and agents jointly; increase concurrency only when the ready work is genuinely independent.

Finish the accepted program, including integration and correction, rather than returning after a first patch. Close in the order CE QUALIFY → GH ACCEPT → CE RELEASE → GH RELEASE, then close local coordinators and aggregates. Qualify changed code; reuse valid evidence for unchanged source rather than launching another full campaign for administrative closure. Publish the exact source pair and explicit limitations. Stop before choosing the next biological experiment.

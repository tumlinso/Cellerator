# Execution and context strategy

Use the run charter for intent, the relevant outcome sheet for local responsibility, and exact source/evidence references as needed. Machine inventories and old catalogs are lookup material, not mandatory context for every child. The root should read architectural rationale once, then send the subset relevant to each delegation.

A useful delegation contains the concrete desired outcome, why the boundary matters, current source/worktree identity, actual authority/ownership, required interfaces and acceptance, choices left open, and the expected compact handoff. Preserve counterevidence and uncertainty. Do not send all three scientific essays, every old Todo or the full run history to a routine implementer.

The observed live Codex config sets Terra/medium for both its default root and default children, with eight spawned threads per session. The user's intended NF1A root is Astra: select it for this launch, not by replacing all defaults. Named roles were described by live AGENTS.md but their individual files were not exposed through the façade; their effective models/efforts must therefore be verified locally. Do not report Luna/Sol settings as already verified. Custom-agent overrides and inherited runtime permissions require effective-setting checks [W1]. No child may self-promote or silently fall back to Astra.

Most focused implementation can use the configured cheaper implementer. Scouts locate evidence rather than decide architecture. Use a capable reviewer for consequential numerical/lifetime/semantic changes and final integrated claims, not every trivial edit. A parallel head is optional only for a substantial coherent stream whose context and coordination burden genuinely merit it. A Cellerator coordinator delegate required by local authority is not automatically a second architect or an expensive head.

A durable outcome can include many ordinary steps and several transient helper calls. A genuine independent writer needs proper native ownership and isolation; a helper conversation is not a substitute for a first-class lane. Conversely, do not manufacture a durable Todo for each compile, inspection, test or review message. Let the root create a new record only when persistence, ownership, independent acceptance, significant risk or a real dependency justifies it.

Use the smallest relevant read. When exact source is known, read it directly. A broader local investigation is useful to locate unknown evidence, with two independent questions and compute_profile=narrow. Its interpretation is subordinate to root reasoning. Do not ask it to design the campaign or repeatedly retry an inaccessible façade. In this review direct façade reads succeeded after the scout failed.

## Useful concurrency, not a fixed wave script

Prepare only a useful frontier. CORE/SYSTEM may own the central build files initially. Their local integrators start once that producer outcome completes, before the other producers have finished. This orders central-file ownership while allowing early integration. Component outcomes can begin preliminary work before their finish prerequisites; they cannot complete until actual required capabilities are present in the coherent source they tested.

Start with a small number of substantive children; expand only when independent ready work, memory, build capacity and integration throughput justify it. The observed Codex thread ceiling is not a command to fill it. Avoid many agents simultaneously reading the same subsystem or building the same dependency. A focused direct root change is permitted when dispatch overhead would dominate and the root holds the appropriate write claim/workspace. Otherwise use the existing owner or a canonical ownership transfer; a read-shared coordinator seat is not unrestricted write authority.

## Conditional work with the currently verified kernel

Native decision-value prerequisites exist. This review did not establish a general lazy-template materializer or automatic selected-branch join in the deployed kernel. WorkProfile has a strict presentation type but is not visibly persisted by native plan apply. Therefore this package does not invent those fields in its native plan.

Keep ordinary alternatives inside their durable outcome. Record the selected mechanism and evidence; materialize an additional task only for an actual independent boundary. If the root uses a native decision guard, insert only the selected executable branch and make the join depend on that branch plus unconditional prerequisites. Do not precreate every alternative as an unfinished child of the aggregate: the verified aggregate rule waits for all children to be done, including otherwise inactive alternatives.

The work-profile sidecar is a reviewed routing aid, not falsely claimed native authority. Concrete model/effort belong to execution policy and observed attempts, not permanent task semantics. There is no tooling rewrite prerequisite to this campaign.

## Reuse evidence at the right level

Local iterations run the affected tests. Producer acceptance qualifies its source and interfaces. Integrated acceptance rechecks interactions and actual external consumption. Administrative RELEASE checks that the accepted source/evidence pair is still the pair being published; it does not unconditionally rerun every test. Changed source, build policy or dependency requires the appropriate requalification, not a fabricated inheritance claim.

Record total usage when observable, elapsed execution, repeated reads, build/test work and time-to-first-real-consumer. Eighteen records instead of 120 unfinished records is a structural reduction, not a measured percentage reduction in credits or completion time.

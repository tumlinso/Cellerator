# Two authorities, one scientific direction

Both GH-ML2 and CE-ML2 plans are part of the intended program. CT is physically in the CE repository and shares its authority. Native kernel expansion is conditional; composable framework integration is an explicit delivery.

The GH main thread owns the scientific question and interprets the experiment. CE owns native/CT implementation decisions within the agreed mathematical demand. A separate CE claim/session is needed for CE writes; it may be held by the same main process where the tools support that or by a first-class CE delegate. Bounded GH children never gain cross-repository write authority. Do not create fake foreign task dependencies or merge ledgers.

## Start useful work immediately

GH DESIGN supplies a short provisional demand: expression, biological modeling assumption, source/target axes, trainable quantities, permitted evidence, gradient actions and representative shapes. The supplied worked candidate is enough to begin a reference. GH DATA and simple Torch code can proceed independently. CE TRAIN already has a source-confirmed integration gap and can begin without waiting for completed biological data or the final GH model.

Refine consequential semantics before committing a new native operation. Ordinary adapter/build/test work does not need repeated signoff. GH's LEARN outcome requires the actual CE TRAIN producer path for final qualification but can develop with a clear reference in the meantime. CE BIO follows the chosen construction and can end in reuse or non-promotion with a correct path. GH PILOT compares the resulting path rather than waiting for every hypothetical candidate.

## Deliver and consume

Use one small producer receipt: exact source/build or installed package identity, operation contract, supported widths/dtypes/derivatives, parameter/update ownership, test evidence, performance disposition and limitations. The GH consumer adds its exact installed integration result. A bare commit is not numerical qualification; a compiled header is not a working training path.

The joined acceptance waits only for unconditional outcomes and the selected realization. There is no producer dependency on a completed consumer that itself awaits the producer. Do not require matching origin/main or force pushes just to accept a local development slice; record exact tested identities and follow normal repository publication policy.

## Native language and existing work

Preserve Cellerator's native C++ route, `.cell`/compiler semantics and existing CEIR/stdlib ownership. A composite operation may initially be native calls or CT composition. Full-language or arbitrary Torch compilation is not a gate. A needed change to compiler-owned paths requires a scoped supported plan amendment, not a new GH IR or unauthorized directory write.

Old L1 plans were proposed in this conversation, not a mandate to retire any live records. At adoption, check current state. If useful work has since landed, keep it and record narrow dispositions. The observed stale legacy-workflow warning is not permission to reconcile or delete historical NF1 records. Escalate only an actual blocking authority problem, with a preserved checkpoint; do not repair workflow infrastructure inside this science package.

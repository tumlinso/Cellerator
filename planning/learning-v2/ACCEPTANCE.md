# Acceptance: few outcomes, real evidence

Task completion contracts are the acceptance requirements. Bind actual executable required gates through the current `coordinate_task(action="bind_required_gates")` mechanism once the commands exist. `finish_task` runs them. The archive intentionally contains no placeholder `true` gates or invented future executable names. Package lint and algebra witnesses are not product acceptance.

## GlassHelix

Verify the two native repair cases against the real corrected code. Exercise learned shared and local quantities, permitted conditioning, frozen global parameters, intentional non-identifiability and resolution by an added observation. Validate missingness, actual sampling relationships, clone isolation and prevention of target/ATAC-derived feature access. Connect the same fitted component to native NF1A with matching scientific identity, predictions or selected response. Save/reload underlying values with a scientific manifest.

One end-to-end complete-objective derivative test checks composition. Do not requalify every primitive in every GH model; reusable primitive correctness belongs below it. Do not require every possible model class or one universal uncertainty implementation.

## Cellerator and CelleraTorch

Test native and wrapper forward/gradient parity on the actual supported shape/dtype domain, logical permutations, repeated parameter use, duplicate contributions where supported, trainable zero values and activities, and observation masks relevant to the chosen operation. Verify parameter gradients without learned-value mutation during the new backward, accumulation before one step, update/readiness publication, stale-version rejection and storage lifetime.

Separate registration testing from mathematical derivatives. A numerical finite-difference test must use a suitable reference precision or error analysis; half rounding is not silently treated as an exact smooth function. Do not claim double backward/JVP/vmap/compile/autocast coverage unless executed. Preserve the old explicitly combined-training contract and its valid tests.

Check checkpoint restoration after preparation is rebuilt. A parameter's logical identity must survive changed physical order. The native library must still build without Torch for unaffected targets; CT supplies framework dependencies explicitly.

## Biological ML construction

Test exactly equivalent straightforward and structure-preserving expressions before timing. Identify what is reused or avoided and what data/model conditions are necessary. Include a counter-regime where the benefit disappears or the scientific restriction fails. Report separately: modeling effect, numerical equivalence and computational cost.

Measure one representative whole training lifecycle/iteration: cold preparation, hot forward, backward, update, packing/conversion, synchronization and memory. A small controlled representative plus a bounded real pilot is sufficient initially; no full autotuning campaign or guaranteed speedup. Do not promote a favorable kernel result while total fitting is slower. Evaluate-not-promoted is legitimate with a correct retained path.

## Integrated acceptance

The independent experiment imports installed or explicitly pinned developmental public packages and actually trains a CT/CE-backed component. Raw source inclusion, decorative CE calls or a completely separate GH engine do not qualify. Record the exact producer source/build/test identities and actual consumer check.

Use the existing GPU lease/controller policy for CUDA tests. Missing GPU validation blocks acceptance of the claimed CUDA path. Missing biological inputs instead leaves a separate biological status; a correctly qualified toolkit/client can still be delivered. No numerical performance victory or molecular discovery is needed to accept engineering progress.

Keep the final report short: selected assumptions and branches, actual tests, supported capabilities, one invocation, measured total costs, remaining gaps, and distinct toolkit/client/biology/performance status. Task evidence and one producer/consumer receipt are sufficient; do not create another status bureaucracy.

# Design overview: make the next good idea cheaper to build

The central change is to make **Cellerator the normal place where reusable biological mathematics is expressed, differentiated, prepared and executed**. GlassHelix becomes a coherent scientific experiment on that substrate; Baseplane becomes a coherent sequence-grounded representation/query tool with an independent exact core. The programme does not finish these libraries into a rigid architecture. It gives current and future mechanisms a simpler route to real consumers and native execution.

## What the live inspection changed in this design

Cellerator already has valuable architecture to retain. Ordered indexed incidence, canonical parameter masters, saved forward tapes, value generations and prepared execution exist. Replacing them with a new universal runtime would duplicate precisely the hard ownership work already done. The design integrates new mathematics into those facilities and questions only the abstractions that obstruct actual composition. [CE01–CE03]

Packing already has a more general idea than one frozen physical image: the occupancy oracle accepts independent row/feature orders, while a frozen feature-first plan and a CPK1 N=1 provider are narrower. That is the concrete seam for alternative algorithms. A packer chooses a realization; it does not define all semantic geometry. The new contract accepts caller-supplied, identity, Cellpack, operation-oriented, two-sided and mixed-region strategies without requiring every result to look like Cellpack. [CE04–CE05]

A target-level dependency issue needs deliberate treatment. Cellerator's sequence bridge consumes Baseplane's exact core, while newer Baseplane mathematics consumes Cellerator. This should not become a package-wide cycle. Keep both cores independently buildable, make the bridge depend on both, and let BP's higher representation components consume selected CE numerical components. [CE06, BP01–BP02]

There are two separate Cellerator moonshot campaigns, and their numerical providers overlap in purpose without being identical. One serves Baseplane's effect/refinement work; the other explores single-cell matrix/private-state/response machinery with GlassHelix. The successor preserves both portfolios, their accepted implementations and their missing qualifications. It is not a third sandbox beside them. [CE07, CE09, BP03–BP04, GH03]

GlassHelix's actual current experiment matters. Its ML2 work concerns an audited CellTag cohort and explicitly avoids invented individual trajectories or paired modalities. The reorganization must integrate that real scientific client rather than defaulting to an older remembered dataset or requiring a convenient synthetic win. [GH01–GH02]

Sources moved during inspection, and active-run labels do not tell the whole scheduling story. The follow-up therefore requires current completion, patch/source reconciliation and a fresh baseline before activation. It does not treat this package's observation as current task authority. [GH04; evidence/authority-observation.json]

## The engineering shape

CE describes logical work, prepares one or more realizations and binds values for execution. First-class scalar/matrix patches and actor-private or ragged hidden state retain meaningful axes, readout roles and typed support. Packing can change state access and operation cohorts independently. Derivative requests, runtime activity and numerical zeros are not conflated. Parameters, tapes and structural publication have one owner.

BP connects exact sequence, source/occurrence identity, effect summaries, learned or chosen hierarchy, question-driven refinement, global candidate directories and edit-aware reuse. Clients may use a subset. The API must allow multiple representations and routing methods rather than forcing every base through one dense embedding network—or freezing the project as a motif scanner.

GH connects scientific problem specification, actual data and splits, models, inference, perturbations, evidence and replay. It consumes CE numerical operations, including learning/dynamical primitives. Scientific decisions remain in GH; reusable math does not need to be reinvented there. A new experiment should require a new hypothesis, not another runtime.

## The new mathematical connections

An affine effect can carry an accumulated readout, letting composition preserve both a state transformation and its declared observable history. A finite routing state can carry a continuous affine effect, connecting grammar/context control and learned numeric state. Matrix-polynomial dynamics admit an exact fixed-parameter delta law with a necessary quadratic cross-term, making genuinely low-rank changes a possible computational advantage. Boundary-port elimination can expose a compact regional response while retaining a recoverable interior.

These join response-jet caching, requested-derivative compilation, residual-backed multilevel operators, independent state/cohort placement, guarded specialization, contextual world sharing and supplied coordinate/refactoring operations. Exact identities, restricted model families and approximations are separately labelled. The package contains references and tests for the concrete identities; native integration and measured selection are implementation work.

## The execution programme

There are **19 Cellerator outcomes, 13 Baseplane outcomes and 13 GlassHelix outcomes**, plus one closure epic per repository. The first three small foundations unlock **17 independent domains**. Explicit integration tasks accept their patches into a common source lineage; later workers cannot depend merely on “done” flags in isolated worktrees. CE has a second parallel mathematics/execution wave. BP and GH then join the actual installed numerical provider; a final bounded witness proves all three can compose without losing meaning.

The plan provides 35 lane definitions, not a request for 35 simultaneous agents. The default budget is eight live agents total, with no nested worker-planner hierarchy and one clean GPU timing job at a time unless the current resource authority explicitly supports otherwise. Native and framework handoffs require real source-bound evidence. No current tasks are interrupted or superseded by the package.

## What counts as success

A user can install the appropriate components, run a real problem and inspect which mathematical/packing path was selected. A contributor can add a packer, operator or question without touching a dozen central files. The library can exploit raw hardware where useful without imposing overhead on direct paths. End-to-end measurements include preparation, reuse, derivatives, invalidation and data movement; losing but meaningful alternatives remain available and explained.

The sealed package includes a 92-entry seed preservation ledger and a separate 33-entry historical BitOp map. These are expanded from the finished predecessor state into an explicit live disposition ledger. A polished directory tree without these working properties does not satisfy the programme.

Source labels resolve to exact inspected paths, ranges and commits in `evidence/source-ledger.json`. Primary hardware/prior-art references are in `evidence/RESEARCH_SOURCES.md`. Actual authoring checks and limitations are in `evidence/validation.json`.

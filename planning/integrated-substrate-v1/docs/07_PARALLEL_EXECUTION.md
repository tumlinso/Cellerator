## Staging and native plan adoption

The artifact can be inspected and tested outside the repositories. Do not stage/commit a new planning package into provider repositories while predecessor source-bound acceptance is still running: even an unrelated commit can invalidate an exact-HEAD receipt.

After the predecessor barrier is verified, dry-run `tools/stage.py` for each explicit repository. An approved `--apply` copies only the sealed package to a new `planning/integrated-substrate-v1` directory; it refuses overwrite and never imports a plan. Commit reviewed planning inputs according to the existing workflow, create ignored `local-config.json` files, and refresh the global activation review against the resulting heads. The scope/claim review must include intended integration worktrees, not only clean `main` directories.

Run native `plan_preview`/validation on each staged plan. Review the real diff, task IDs, lane workspace policies, local predecessors, gates, command paths and current observation preconditions. Adapt the plan through supported interfaces if schema details or source destinations changed. Apply the three plans independently with fresh local preconditions. Keep them undispatched until all three imports and the global review are accepted. A partial import is inert planning to reconcile, not a reason to start coding or mutate another authority.

No automatic supersession is specified. Completed predecessor epics remain completed history. Map their still-open research obligations into the successor; only an explicit current authority review can reconcile contradictory remaining records. Do not blindly execute an old package's optional supersession script.

## Waves and source ownership

After the three small ADOPT foundations, the graph exposes **17 independent domains**: six CE, six BP and five GH. This is available parallelism, not a requirement to start 17 expensive agents at once. Initial policy: at most eight live agents total, including root and any necessary coordinator seats. Adjust to the actual configured budget; avoid idle supervisor hierarchies. Existing resource authority determines GPU leases. Only one clean timing job runs by default; ordinary CPU/source/test work can continue in other lanes.

CE merges a first usable substrate before the second mathematical wave. That wave contains strategies, new mathematics, differentiation, adaptive reuse/refactoring and hardware lowering. CE then integrates the existing framework adapter and publishes a real installed numerical handoff.

BP and GH can perform their independent source/domain work without waiting for all new CE math. Their **native provider joins** wait for the CE handoff, then their coherent tools are exercised. GH's final joint interoperability witness additionally waits for BP's final capability handoff. There are no cyclic cross-authority dependencies.

All independent leaves use isolated-merge workspaces and point to an explicit integration task. A leaf's only immediate source-consuming dependency is that integration task. Provider joins and sequential tool-composition steps run in the accepted integrator lineage, so a task completion flag cannot strand needed files in another worktree. The static validator checks this property. Downstream worktrees must be created or reconciled from the actual accepted intermediate commit, not the initial ADOPT branch.

Root build files, shared registries, common headers and inter-package interfaces have one integration owner. A worker may propose a patch outside its write scope but does not apply it concurrently. Leaf-local build fragments and fixed semantic contract fixtures allow parallel development. If a discovered better source layout needs different scopes, preview/reconcile those scopes before dispatch; do not freeze a bad architecture just because this package proposed folder names.

## Agent packet and reporting

Give a worker its task brief, the accepted base commit, the relevant short contract(s), source ownership and direct paths to predecessor implementation/evidence. Do not make every worker read the whole conversation, all 48 cards or every status ledger. The root retains the programme charter and preservation map. The local observer model is an evidence scout, not a planner or mutation worker.

A worker returns code, the tested accepted base/commit or patch, actual capabilities, unsupported cases, relevant test/benchmark artifacts and any requested shared changes. Root integrates and checks the combined result. Use coarse outcomes; ordinary inspection, failed compilation and repair are not new tasks. Failed mathematics or a losing kernel gets a truthful disposition and reusable evidence, not a false validated completion or a wholesale restart.

Bind executable acceptance commands to the native task lifecycle as they become real. A brief's prose completion contract is not a substitute for tests. Do not bind an invented future command as if it already passes. Completion contracts distinguish host semantic checks, native execution, installed/framework consumers, GPU performance and scientific evidence.

## Capability handoffs

`machine/cross-authority.json` defines the provider joins. Each local join has a real command gate and the controller also checks it before dispatch. A provider receipt names the exact provider task, source commit, installed build artifacts, actual call paths, supported shapes/numerical policies, real successful checks and limitations. Evidence is hashed; mock/reference-only checks cannot stand in for native SM70 execution.

Publish receipts after committing the tested source into ignored `receipts/`, not by committing a receipt that immediately changes the HEAD it asserts. Store/check actual evidence via the existing artifact workflow; ignored does not mean disposable. A source change requires a refreshed compatible receipt and relevant check. Later source-manifest-based reuse may reduce unnecessary revalidation, but must identify all real build dependencies rather than silently ignoring edits.

Provider checks inspect only the provider and sibling sources actually named by its evidence, so unrelated dirty worktrees do not serialize the programme. Exact provider HEAD checks are intentionally conservative cold integration gates, not per-step runtime overhead. A healthy implementation should not need to read authority or hash source files inside mathematical execution.

## Stop conditions and useful continuation

When predecessors are unfinished, report the exact blocked roots and stop the bootstrap; do not take over current work or run a polling loop. When one new domain fails, pause its dependent region and continue independent work. When an external dataset/toolchain/permission is unavailable, preserve the blocked obligation and do not substitute a mock result. When source changes, reconcile the affected base and capability rather than restarting every completed domain.

Closure requires usable integrated paths, explicit capabilities, real alternatives, preserved research and easier extension. It does not require that every speculative mechanism become the fastest default or that a biological model discover a uniquely identified truth.

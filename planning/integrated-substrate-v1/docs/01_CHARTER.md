# Charter: integrated tools that remain easy to invent with

## The user's instruction, not an inferred product roadmap

These repositories are unfinished research software. This successor must make the next good idea easier to express, benchmark, compose and optimize. It must not turn them into finished, rigid frameworks. The objective is deliberately designed, extensible, fast libraries and a usable scientific experiment—not a directory cleanup, another collection of standalone demonstrations, or a universal new intermediate representation.

Cellerator is the mathematical library. General dynamical computation, learning-related mathematics, local latent-state transformations, differentiation, response operators, execution planning and hardware realization belong there when reusable. GlassHelix is the scientific experiment built on it. GlassHelix chooses hypotheses, data semantics, losses, candidate interpretations, interventions and scientific acceptance. A reusable operator does not have to mature outside Cellerator before belonging to it. Baseplane owns exact sequence meaning and the sequence-grounded construction, questioning and refinement of hierarchical representations; general numerical mechanisms it uses belong in Cellerator from inception.

Compatibility with historical names or APIs is not required. Preserve behavior, ideas, meaningful evidence, real sibling consumers and the ability to develop—not accidental file layouts or duplicate implementations. The existing owners of memory, parameters, tapes, prepared programs and identity are assets. Extend or simplify them before proposing replacements. Do not create a fourth coordinating math framework.

## Non-negotiable outcomes

1. A user can build and install supported components, create a real problem, choose or supply a packing strategy, prepare it, bind state, execute it, request supported derivatives, and inspect what was selected. The default route does not require importing an experiment directory or compiling a sibling's private sources.
2. A contributor can add a useful operator or packing algorithm without changing a giant switch, a dozen administrative files or the scientific meaning of the input. There remains a direct path to raw CUDA, registers, explicit layouts and instructions.
3. The supported fast path has explicit storage ownership, streams, capacities, snapshots, generations and output contribution rules. Preparation and optional diagnostics stay outside hot loops. There is no mandatory allocation, host synchronization, canonicalization or generic interpretation per step.
4. All existing valuable mechanisms and outstanding obligations have a destination and an evidence-preserving disposition. Unsupported, unsuccessful and unfinished mean different things. A negative executor result is not a refutation of its mathematical operator. An unqualified prototype remains discoverable and callable through an experimental component where appropriate; it is not silently advertised as a supported default.
5. End-to-end improvements matter: cold preparation, amortized reuse, numerical quality, learning/derivative cost, invalidation and memory traffic count alongside inner-kernel time. A coherent redesign is allowed to win by removing work, not just by executing the old work faster.

## What this run does not authorize

Do not interrupt, supersede, reopen or take over current ML2 or either moonshot campaign. This is their successor. Do not reactivate permission-gated Ampere work merely because an old run is labelled active. Do not mutate CellShard's authority, edit preprints, write Todo databases or generated views by hand, or silently discard historical evidence. Do not force all scientific tasks to use one state family. Do not require biological identification before integrating an experimental mathematical operator.

No compatibility constraint does not mean no correctness constraint. Argument order, repeated arguments, logical IDs, exact sequence coordinates, validity, whole-candidate hypotheses, parameter ownership and derivative conventions survive a reorganization unless an explicit model change is being made.

## Design economy

Use the smallest shared contract that makes two actual consumers simpler. Prefer a cold host callable or small function table for packing over a dynamic plugin ecosystem. Prefer flat typed descriptors and existing ownership handles over a class hierarchy. Keep experimental additions cheap: reference implementation, explicit capability record, focused correctness checks, one meaningful consumer, one comparison. Default promotion additionally needs measured evidence for the claimed regime.

Count extension friction during the final exercise: independently add a packer, a mathematical primitive and a Baseplane query. Report central files touched, additional copies/launches, required boilerplate and unsupported cases. There is no arbitrary score target: eliminate unnecessary coupling revealed by the exercise before closure.

## Permission to be ambitious

Search beyond conventional neural operators. Treat exact and approximate algebra, support words, private coordinate systems, regional response maps, factored relations, effect composition, residuals and the full relevant GPU execution model as design material. A creative proposal needs a precise function, meaningful axes, an execution mapping, a derivative policy and a falsifiable comparison. It does not need to resemble a conventional ML layer.

Do not use “integration” as a reason to stop inventing. Do not use “invention” as a reason to leave another orphaned fast kernel.

The dependency/integration map explicitly separates project authorities, uses mirrored version/hash receipts, assigns central files to integration and warns that historical active runs are not new work. We adopt those bootstrap/coordination lessons, not its superseded allocation of compiler responsibilities to CellShard.

## CCP1

The inspected compiler Part One package adds a native schema-3 apply plan distinct from the richer proposed catalog, workstreams, first-class lane queues, barriers, task-owned checkpoints, per-task detail and substantial source inventories. Its older manual command resolution was incomplete. We retain its artifacts and explicit ownership style but do not copy unresolved apply/activate commands.

## Semantic Spine

The inspected Semantic Spine package makes prospective demo code and declaration-only contracts concrete without pretending to ship their implementation. It rejects schema-2 downgrade, fake GPU fallback and unsupported native-validation claims. We retain those distinctions. A source-shape probe is not full final-plan validation.

## Relation Update Spine

The inspected RU1 package provides deterministic schema-3 projection, manifest/delivery binding, graph/scope validation, real CTest inventory checks, a manual preview/apply interlock and a pinned Project Control native bridge. We generalize these into two packages with cross-authority checks and a single-controller charter.

## A lifecycle correction

The later RU1 tooling record states that native run creation inserts an active run and that no distinct planned/paused run activation API was present. Therefore NF1 import may create active run metadata but does not create claims or dispatch workers. Do not print a fictional activation command. The user later launching the controller is the operational authorization to execute the program.

## Hash provenance caveat

RU1's corrected tooling record names the installed mutation-module SHA256 as `3d8558670bb66a3d03614126236582f27649d91b16589a615e379fa4f74282a9`. The current source reader supplies a different `file_identity` string for the repository file. We preserve the installed-module pin from the corrected predecessor and record the reader identity separately. We did not read the local installed module bytes in this container. If the configured runtime does not match, the bridge refuses to import until installed source is reviewed and the package's tooling contract is deliberately revised.

# BP-MOON-140 — Compose mechanisms into alternative Baseplane paths

## Outcome
Build several end-to-end sequence-grounded combinations, keeping more than one architectural ontology alive. Include actual candidate construction and a refine/revisit path, not an oracle packet or disconnected kernel collection.

## Read first
`docs/00_INTENT.md`, `docs/01_REPOSITORY_REVIEW.md`, `docs/03_VOLTA_PALETTE.md`, and `AGENT_HANDOFF.md` in the installed planning package. Read only the source anchors needed for this outcome rather than repeating a repository-wide investigation.

## Authorized write scope
`experiments/moonshot/compositions`

Everything else is read-only unless the root changes scope through the installed authority. Family agents propose shared-seam changes in their own handoff; the integrator owns application. This Baseplane task does not write the Cellerator, GlassHelix or CellShard repository or any Todo database directly. Cellerator numerical experiments have their own authorized companion tasks; this is an authority boundary, not a prohibition on Cellerator research.

## Experiment cards
See the package outcome and composition specifications.

## Work style
Implement representative mechanisms immediately. A good family result contains genuinely different computations, not four wrappers around one kernel. Investigate unexpected elegant mechanisms and adapt the family through the root. Do not wait for all old CPU/CUDA roadmap work, API freeze, large datasets, or proof of a speedup. Reuse existing correct substrate and CUB where it keeps the idea small.

## Minimal receipt
State what was authored, compiled, run and compared, with commands and file paths. A compile failure or unavailable GPU remains explicit. Document source support, loss/revisit behavior, buffer/counter policy and one semantic distinction from a competing design. Every assigned card needs a disposition: implemented experimentally, combined into a named artifact, rejected with a concrete reason, or deferred with remaining scope. Never relabel an unimplemented design as implemented.

## Stop and continuation
Stop a branch for an unsafe execution path, unbounded resource requirement, ownership conflict, incompatible hardware instruction, or a discovered semantic contradiction. Fix a trivial issue; otherwise isolate it and continue a different idea. Do not exhaust the campaign debugging one speculative branch. Do not benchmark broadly or silently start multi-GPU jobs. Preserve all source and receipts.

# What Baseplane is supposed to become

## Recovered intent

Baseplane asks whether an entire genome can become useful computational context without first expanding every base into an equally expensive dense latent vector, and without first supplying a complete annotation of which sequence matters.

The destination remains **hierarchical, learned floating-point representation**. Exact packed DNA, Boolean masks, integer tags and finite-state effects are useful ways of grounding, organizing and routing information toward that destination; they are not an excuse to replace the scientific question with a motif-scanning library. The hierarchy should emerge during encoding and interaction with learned computation. It may use previously learned machinery, multiple passes, preprocessing and cached structure, but must not hide an oracle that already knows the genome's useful hierarchy. [Repository R01–R04]

The distinctive programming idea is to make information carry much of its own control state. Sequence-derived masks, tags, supports, candidate keys and refinement requests determine what moves, combines, becomes expensive, or is revisited. Warp collectives and compact representations can keep execution coherent while biological information follows different paths. This does not mean banning every CUDA branch: a uniform branch, a cheap per-thread path or a conventional CUB primitive may be the cleanest implementation.

Genomic locality is a cheap computational affordance, not a mandatory biological distance penalty. Nearby sequence can be processed cheaply; learned or discovered relations may bring distant sequence together. Neither a fixed cis/trans architecture nor a predetermined mapping from biological levels to warp/CTA levels is required. Hardware tiles are work units, not evidence of functional boundaries. [R02–R04]

The larger program still has distinct responsibilities. Baseplane grounds information in exact sequence. Cellerator owns shared numerical execution, operation planning and the common biological interface, including experimental learned mechanisms and ML-like mathematics from inception—not merely qualified kernels. GlassHelix models evolving biological state and investigates mechanisms. CellShard handles distributed execution/storage. The paired Cellerator tasks may build Tensor Core mechanisms, small learners and new parameterized operators immediately. Baseplane owns their sequence-grounded use, not a second general numerical framework. Experimental status is not an ownership boundary. [R04]

## This campaign's deliberate change of emphasis

The user explicitly authorized broad invention, unusual mechanisms and lightly qualified implementation. We should create many concrete possibilities before deciding which survive. The previous lab's requirement to retain at most two mechanisms does not govern this workshop. Existing negative evidence remains valuable, but it does not prohibit a different representation, different workload, or a new composition.

The output of this planning pass is an implementation-ready bootstrap plus original seed code. The later implementing agent is expected to expand the research library, not merely rewrite the documents. The package does **not** claim that all 48 catalogue ideas have already been implemented, that CUDA seeds have compiled, or that the live TODO authority has changed.

## Preferences to preserve

Treat the full target machine as design material: bitfields, packed integer arithmetic, predicates, shuffles, register layouts, shared-memory exchange, caches, texture paths, FP16/FP32/FP64 arithmetic, Tensor Cores and instruction compositions. High-level frameworks are tools, not the definition of the solution space. Use Volta specifically, not a mental model accidentally borrowed from Ampere or Hopper. [S01–S06]

Keep tasks coarse enough that an intelligent root and bounded delegates can adapt. Do not turn every interesting thought into a new orchestrator task or every test into a gating ceremony. Conversely, do not hide unfinished work: each experiment has an explicit disposition and a clearly named next step.

## What is established, what is hypothesized

**Established in the inspected repository:** exact-sequence substrate and contracts exist; the full old BitOp executor roadmap remains deferred; four small CUDA lab mechanisms were evaluated; no trained genome-wide Baseplane representation is established. [R05–R15]

**Working scientific hypothesis:** useful representation and expensive computation can scale more closely with active task-relevant biological structure than with a fixed dense expansion of genome length. There is no guarantee that every task has a small sufficient representation.

**New proposals in this package:** regions as composable effects; residual-backed refinement; real global candidate directories; learned-to-instruction compilation; query-driven execution; context-aware repeat sharing; boundary-port and counterfactual experiments. These are design hypotheses assembled from research and machine reasoning, not claims recovered verbatim from the user or proven by the cited papers.

## Non-negotiable distinctions

Source recovery is not lossless embedding. Data lineage is not a biological explanation. A relation candidate is not causality. Predictive surprise is not importance. A hash key is not identity. A local warp match is not a global search. A compiled kernel is not a speed result. A successful synthetic fixture is not a trained genome model.

These distinctions keep the invention space open: we can try strange mechanisms without first pretending they are validated biology.

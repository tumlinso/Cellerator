# E30 — State-conditioned predicate banks

Numerical owner: `CE-MOON-040` in Cellerator. Sequence consumer: `BP-MOON-090` in Baseplane. Numerical implementation location: `experiments/baseplane_moonshot/families/learning/e30`.

## Question
Can a fixed set of cheap predicates adapt to the current cell without scanning with a large neural model?

## Concrete mechanism
Learn a small state-to-bank selection or mixture over reusable sequence predicate circuits. The current state selects compatible banks or thresholds; predicates remain exact conditional questions, while bank choice is a learned hypothesis.

## Mapping onto Volta
State scoring in a small dense/DP4A tile, predicates in bitplanes, cohort scheduling by selected bank.

## What this does not establish
Avoid a bank for every possible state. Keep identity, selection provenance and weight/state versions; bank choice does not change exact motif semantics.

## First small executable probe
The same exact sequence under two synthetic states requests different predicates and yields source-grounded outputs.

Write a scalar or algebraic fixture and the smallest representative machine path. Prefer one intelligible executable mechanism over an empty API shell. Leave alternative variants visible. Record a failed compile or unresolved semantic issue instead of hiding it or spending the whole campaign on qualification.

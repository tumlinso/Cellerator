# E25 — Query-pull refinement

Owner: `BP-MOON-080`. Suggested implementation location: `experiments/moonshot/families/demand/e25`.

## Question
Can expensive features be computed because another layer asks, rather than because every base passes through the same network?

## Concrete mechanism
Send a question plus current tolerance/state version downward. A region returns an answer from its summary, a certified bound, or a request for child detail. Batch unresolved requests by operator and depth; produce only the richer floating objects required by the active questions.

## Mapping onto Volta
Queue compaction, masked tree traversal, warp-cooperative source fetch and small numerical kernels.

## What this does not establish
Query-specific sufficiency is not universal sufficiency. Learned confidence is not a proof of absence; keep an exploration/replay route.

## First small executable probe
A scalar max query can safely prune with a true bound; demonstrate that a different query cannot reuse that certificate.

Write a scalar or algebraic fixture and the smallest representative machine path. Prefer one intelligible executable mechanism over an empty API shell. Leave alternative variants visible. Record a failed compile or unresolved semantic issue instead of hiding it or spending the whole campaign on qualification.

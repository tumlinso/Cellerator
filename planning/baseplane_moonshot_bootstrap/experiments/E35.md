# E35 — Query-support memoization

Owner: `BP-MOON-100`. Suggested implementation location: `experiments/moonshot/families/incremental/e35`.

## Question
Can a remembered answer declare exactly what changes would invalidate it?

## Concrete mechanism
Cache answers with their query, sequence, weight, cell-state and representation versions plus an exact or conservative dependency support set. Reuse only when both identity and support checks permit it. Distinguish result caches from cached computation plans.

## Mapping onto Volta
Compact version tuples, support masks/intervals, hash lookup and batched validation.

## What this does not establish
An attention or pooling answer may depend on negative evidence from many inspected regions; positive hits alone understate support.

## First small executable probe
An edit outside a true support set preserves a result; changing query or weights invalidates it.

Write a scalar or algebraic fixture and the smallest representative machine path. Prefer one intelligible executable mechanism over an empty API shell. Leave alternative variants visible. Record a failed compile or unresolved semantic issue instead of hiding it or spending the whole campaign on qualification.

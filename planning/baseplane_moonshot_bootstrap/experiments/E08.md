# E08 — Small-state weighted alternatives

Owner: `BP-MOON-030`. Suggested implementation location: `experiments/moonshot/families/automata/e08`.

## Question
Can a region carry several possible state transitions instead of a single deterministic interpretation?

## Concrete mechanism
Use tiny weighted automata with sparse destination masks and scores. Try probability, max-plus and Boolean relation versions as different algebras. Compose sparse rows and prune only under a declared approximation policy; retain alternatives for later queries.

## Mapping onto Volta
Mask intersection, shuffle, FP32 FMA or add/min/max. Ordinary MMA is not a native max-plus operation.

## What this does not establish
State/edge count can grow; exact and pruned results need different tags. Normalization is not evidence calibration.

## First small executable probe
Two paths that merge into one state, and a case where pruning the locally weaker path changes a later answer.

Write a scalar or algebraic fixture and the smallest representative machine path. Prefer one intelligible executable mechanism over an empty API shell. Leave alternative variants visible. Record a failed compile or unresolved semantic issue instead of hiding it or spending the whole campaign on qualification.

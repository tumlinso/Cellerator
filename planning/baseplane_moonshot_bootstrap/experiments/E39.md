# E39 — Question-specific summary portfolios

Owner: `BP-MOON-110`. Suggested implementation location: `experiments/moonshot/families/hypotheses/e39`.

## Question
Can different future questions receive different compact summaries of the same region?

## Concrete mechanism
Maintain a portfolio: counts for abundance questions, effects for state propagation, extrema/bounds for pruning and small learned vectors for similarity. Queries select the representation they need; unsupported questions cause source replay rather than forced use of one universal vector.

## Mapping onto Volta
Typed sidecars, compact tags, opcode cohorts, narrow numerical paths.

## What this does not establish
Multiple summaries cost memory. Sufficiency is stated per question family, not globally for biology.

## First small executable probe
Construct two sequences with equal counts but different order: the count query agrees and the effect query must not.

Write a scalar or algebraic fixture and the smallest representative machine path. Prefer one intelligible executable mechanism over an empty API shell. Leave alternative variants visible. Record a failed compile or unresolved semantic issue instead of hiding it or spending the whole campaign on qualification.

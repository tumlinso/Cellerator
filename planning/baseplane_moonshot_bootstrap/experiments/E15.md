# E15 — Precision as a refinable resource

Owner: `BP-MOON-050`. Suggested implementation location: `experiments/moonshot/families/hierarchy/e15`.

## Question
Can latent information remain as coarse bits until a query needs more precision?

## Concrete mechanism
Encode selected latent coordinates as sign/exponent class plus successive residual planes. Carry a conservative interval where possible; evaluate easy decisions with the first planes and fetch additional planes only for ambiguous comparisons.

## Mapping onto Volta
Bitplanes, integer comparisons, byte packing, half2 conversion, late FP32 expansion.

## What this does not establish
No implicit claim that a few bits preserve a learned task. Certified interval rejection and heuristic low-precision routing are different modes.

## First small executable probe
Use values straddling a decision threshold and verify only ambiguous items require the next precision plane.

Write a scalar or algebraic fixture and the smallest representative machine path. Prefer one intelligible executable mechanism over an empty API shell. Leave alternative variants visible. Record a failed compile or unresolved semantic issue instead of hiding it or spending the whole campaign on qualification.

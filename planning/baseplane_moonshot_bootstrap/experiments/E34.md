# E34 — Variant-driven dirty cones

Owner: `BP-MOON-100`. Suggested implementation location: `experiments/moonshot/families/incremental/e34`.

## Question
Can a small sequence edit change only the computation it actually affects?

## Concrete mechanism
Maintain reverse dependencies from exact chunks to effects, partitions, posting memberships and query answers. On an edit, invalidate the affected value cone and structural memberships, then recompute to a fixed point or bounded wave frontier.

## Mapping onto Volta
Bitset dirty flags, frontier scan/compaction, versioned arrays and sparse work queues.

## What this does not establish
A local edit can change a global routing key or learned boundary far away. The dirty cone may be large; do not claim constant-time variant scoring.

## First small executable probe
An edited leaf invalidates ancestors plus an affected directory membership, but preserves a demonstrably independent sibling.

Write a scalar or algebraic fixture and the smallest representative machine path. Prefer one intelligible executable mechanism over an empty API shell. Leave alternative variants visible. Record a failed compile or unresolved semantic issue instead of hiding it or spending the whole campaign on qualification.

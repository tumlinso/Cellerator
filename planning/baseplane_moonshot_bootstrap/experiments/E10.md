# E10 — Block-monomial response maps

Numerical owner: `CE-MOON-020` in Cellerator. Sequence consumer: `BP-MOON-040` in Baseplane. Numerical implementation location: `experiments/baseplane_moonshot/families/effects/e10`.

## Question
Can a middle ground between diagonal scans and dense state matrices preserve useful mixing?

## Concrete mechanism
Partition latent state into fixed small blocks. Each output block selects one input block, then applies a small dense matrix and offset. Compose block permutations and block matrices without densifying the block graph. Permit occasional explicit repartition steps outside the closed segment.

## Mapping onto Volta
Register shuffle for block routing; half2 or FP32 microtiles; tensor-core tiles only when enough block work can be packed with meaningful axes.

## What this does not establish
Fixed block structure limits coupling. A general sparse matrix product need not preserve sparsity or this representation.

## First small executable probe
Compose three 2x2-block operators; compare to a dense host expansion without timing.

Write a scalar or algebraic fixture and the smallest representative machine path. Prefer one intelligible executable mechanism over an empty API shell. Leave alternative variants visible. Record a failed compile or unresolved semantic issue instead of hiding it or spending the whole campaign on qualification.

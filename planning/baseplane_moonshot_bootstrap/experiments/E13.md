# E13 — Reversible lifting with residual reservoirs

Owner: `BP-MOON-050`. Suggested implementation location: `experiments/moonshot/families/hierarchy/e13`.

## Question
Can expensive context travel upward while recoverable detail stays off the hot path?

## Concrete mechanism
Split neighboring carriers into coarse and detail through predict/update lifting. Put detail in a separate reservoir, optionally compressed or stored by source reference. Higher layers read coarse values first and selectively pull residuals when their question requires them.

## Mapping onto Volta
Lane pairing/shuffle XOR, FP32 FMA, ballot-ranked sparse residual writes and coalesced sidecars.

## What this does not establish
A retained full residual tree is not compression by itself. Dropped residuals lose information; source availability enables replay, not automatic lossless decoding.

## First small executable probe
Round-trip retained details, then demonstrate that omission changes a query and that re-expansion restores it.

Write a scalar or algebraic fixture and the smallest representative machine path. Prefer one intelligible executable mechanism over an empty API shell. Leave alternative variants visible. Record a failed compile or unresolved semantic issue instead of hiding it or spending the whole campaign on qualification.

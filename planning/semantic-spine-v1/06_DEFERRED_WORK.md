# 6. Deferred obligations, not silently completed capabilities

The following remain explicit obligations after a successful Semantic Spine v1. These are a deferred inventory, **not applied Todos or permission to start additional epics**.

| Obligation | What this epic leaves | What a later completion must prove |
|---|---|---|
| Full `.cell` executable path | Bounded parser/Sema/IR-origin descriptor test | Ordinary `.cell` source traverses the actual driver, planning, preparation and accelerator execution |
| Implicit `.cell` dialect | Architectural commitment; converted content may still use existing pragma mechanics | Extension-driven syntax activation while ordinary C++ remains ordinary |
| Semantic modules/imports | No permanent `.ceh` twin; content preserved as `.cell` | Self-describing interfaces, bodies/summaries, real dependency/link/build handling |
| Cross-translation-unit optimization | Default semantic visibility commitment, subject to effects and numerical law | Real on-demand IR import, joint optimization, cache invalidation and lawful boundaries |
| General relation coverage | Required N1, f16 weights/f32 arithmetic, single device/stream | More widths, types, output modes, concurrency and physical alternatives with tests |
| Contraction integration | Correct scalar-dot versus edge-channel law | Full semantic-to-provider execution and candidate/preparation chain |
| General compositions | Explicit nonprimitive meaning and fail-closed unavailable lowering | Real chain, hierarchy, moments, exchange, gradient and publication composition execution |
| Installed libCellerator and library | Repository-local provisional API/demo | Coherent exported native targets, actual `library/` installation and useful direct consumers |
| Public API stabilization | Temporary lane interface only | Evidence from real consumers before compatibility commitments |
| Performance work | Reachability, correctness, reuse and basic overhead observations | Representative preparation/reuse break-even, geometry scaling, exchange algorithms, stronger provider competition |
| JIT/family compiler | No new implementation | Demonstrated benefit from stable mechanisms, related supports or generated code after complete lifetime accounting |

No final receipt may infer full-language execution from compiler-origin descriptors being passed through C++ test code. No conversion of `.ceh` filenames proves import semantics or cross-TU optimization. No N1 sparse success proves that the best Tensor Core, contraction or exchange providers are integrated.

The user favors automatic cross-unit visibility for `.cell`, no duplicated Cellerator-only header format, and accelerator-oriented optimization with native C++ retaining equal access to the same computation engine. Preserve these design directions without implementing them accidentally inside this small epic.
